# 科学约束下的最小总负担

本模式回答：面对同一冻结任务，哪些完整方案先满足科学与隐私条件，再以足以影响行动的差异减少研究者负担？默认任务选择仍优先减少新增插件、再减少全部插件；旧 `burden_view` 仍只是描述性展示，不改变选择。

新增 `context.burden_decision` 将目标、阈值和完整测量范围绑定到前瞻研究协议。它与风险补测、桥接、组合入口分开使用，不把旧观察改称新策略的确认实验。当前输出是有限候选与已观察完整任务内的偏好，不是未来收益或全局最优的证明。

## 先明确“总负担”的边界

科研质量与隐私是硬条件，不参与加权抵消。通过后，五项指标分开保留：

| 指标 | 记录与使用方式 |
| --- | --- |
| 人工投入秒数 | 原始、有时区的操作者起止计时；同一操作者跨阶段、方案和共同开销不能重复计时；多人并行时间可以累加为劳动量 |
| 已结算现金美元 | 完整任务账目及来源摘要、明细行身份；估价和未知不冒充结算；不把人工秒数折算为现金 |
| 完整任务耗时秒数 | 原始任务开始／结束窗口，包含等待；不能用 CPU 时间、模型记录耗时或各人计时相加代替 |
| 新增插件数量 | 现有目录中去重后的新增依赖；安装状态未知时不能当作零 |
| 全部插件数量 | 传递依赖计入，不能把插件藏在“零插件脚本”里 |

一次测量单位是一个方案在一次重复中完成全部冻结案例的完整任务试次。每个回执绑定该试次全部原始案例记录，失败也必须保留。方案展示值为所有预先安排的完整试次均值；硬上限逐试次检查，不能靠均值掩盖一次超限。没有推测未来复用次数或摊销安装成本。

每项试次均明确覆盖：准备、执行、复核、返工，以及 PVL 材料准备、检查、读报告、误报处理和恢复。每类分别声明人工／现金为完整、不适用或未知，并保留说明。“完整”须有明细；“不适用”不能同时存在明细；缺失仍为未知。上限为每项回执各 10,000 条、整份请求各 100,000 条人工／现金明细。

另外保存一份共同选型开销，绑定全部原始研究材料，只计一次，不复制到每个方案。报告同时展示方案使用负担和本次选型过程总投入，后者包含被排除方案的投入和失败，不等于采用后每次研究的预计开销。失败方案漏记开销也会阻止完整负担决策。完整账本不能小于已绑定的原始运行及补充账本中的已结算现金／人工投入；原有估价不能充当后来实际结算额的下界。

## 冻结策略，而非看完结果再选指标

策略需给出：

- `objective`：优先减少人工、现金、完整耗时、新增依赖、全部依赖，或保留多目标比较 `pareto`。
- 五项指标的 `material_delta`：足以影响行动的差异；它同时限定其他指标可以容忍的变化。
- 五项指标的 `max_value`：可选的逐试次硬上限。
- `local_only`：敏感材料是否必须留在本地；对原生方案与插件方案同样适用。
- `incumbent_plan_sha256`：研究者明确当前采用的完整方案，可为空；不从插件列表猜测。
- 固定范围 `one_complete_frozen_task_no_amortization`。

例如，研究者可以要求“优先减少人工，差异至少超过 30 秒；允许多一个依赖、现金增加不超过 1 美元；完整任务最多 100 美元；数据必须留本地”。这些是一个示例选择，不是工具强加的默认阈值。Agent 应把这些问题用自然语言确认，再组织结构化协议，不要求普通研究者填写 JSON。

只有候选的主要目标改善超过阈值，且其他指标没有超过允许差异的退步，才形成一条偏好。`pareto` 模式允许任一指标有实质改善，但同样不能有超出阈值的退步。`1e-12` 仍只是算术容差，不能当作实用差异或统计显著性门槛。

系统要求候选直接优于每一个其他可行候选才给出明确优选，不按输入顺序逐步淘汰。实用容差可能产生非传递关系；循环和取舍保留为选择题，不偷用插件数或文件顺序破局。所有差异都落在行动阈值内时，可以保留已通过全部门槛的当前方案；没有明确当前方案则保留并列。

## 科学与隐私门槛

科学判断复用 `select_task_plan()` 的原始评估器，重新检查真实授权产物、每个阶段、完整集成、质量下限、回退限制和原有成本覆盖。新策略不能用传入的“通过”标签替代重算。缺少产物根目录时仍为未知；便宜但科学失败的方案直接排除。

原有必需科研复核逐项给出接受、拒绝或未知，以及复核人、来源摘要和说明。拒绝是硬排除，未知阻止决策。要求数据本地留存时，整个方案及其组件必须有范围绑定的隐私评估；违反直接排除，未知不能假定安全。这些复核与隐私状态是提交材料，并未认证复核人身份或自动审计真实网络行为。

隐私与复核回执绑定完整组件、协议和全部原始记录。改变方案、输入或记录后，不能继续复用原回执。符合这些结构检查也不产生科学授权、安装授权、远端调用授权或付款授权。

## 入口与可恢复材料

现有 `plan_plugin_use`／`plan-use` 接收独立模式，六个 MCP 工具签名不变。

准备阶段在 `task_selection.studies` 为空时提交：

```text
context.burden_decision = {
  action: "prepare",
  policy: 用户事先声明的完整策略,
  study_suites: 尚未采集的完整两臂研究协议
}
```

返回协议、摘要和 `prepared_studies`。每个返回的 suite 内已绑定负担协议摘要，lock 绑定修改后的完整 suite。应独立保存这些材料，再采集原始结果；不能继续使用绑定前的旧 lock。

分析阶段使用 `action: "analyze"`，提交原协议及摘要、全部原始 `task_selection.studies`、逐试次 `receipts`、逐方案 `assurances` 和一份 `decision_overhead`。详细格式见 [JSON Schema](../../schemas/burden-decision.schema.json)。案例／方案／记录／原始评估的动态绑定和时间重叠仍由运行时校验，Schema 检查不能替代它们。

旧材料没有前瞻策略绑定时明确拒绝，保留原研究。历史规则或用途可以在原有解释修订机制中重新讨论，但不能仅重写摘要，把事后分析包装为已经预注册的新确认结果。哈希本身不能证明注册时间；真实前瞻性仍需独立保存的协议与过程证据。

合成示例可直接运行：

```text
python examples/task-selection/burden_demo.py --output <新示例目录>
python scripts/value_lab.py plan-use <新示例目录/context.json> --artifacts <新示例目录/artifacts> --verifiers <新示例目录/scorers> --output <另一新报告目录>
```

新入口返回 `route=DECIDE_TASK_BURDEN`。应核对实际返回，不能仅凭版本号推断已安装宿主支持此模式。原研究文件保持不变，结果可作为现有决策存储的新解释材料保存；本模块本身不启动运行或修改历史。

## 验收及证据边界

可复现的八类合成场景覆盖：增加依赖但减少完整人工工作、依赖取舍、微小差异保留现状、PVL 误报工作使选择逆转、隐私违规、科研复核待完成、失败费用未知，以及只追求现金但没有现金改善。

基准例中，原生方案人工 600 秒，插件加已有脚本方案人工 80 秒；二者都通过完整的合成科学检查。声明允许新增一个依赖后，后一方案成为模拟优选。计入较大的 PVL 误报处理负担后，选择转回原生方案。这些数字是制造的测试输入，不是测得的研究者时间节省。

所有场景保持 `SIMULATION_ONLY`，真实 `selected_plan_sha256` 为 null；`computed_state` 和 `simulation_choice_sha256` 只展示规则计算结果。非合成输入的结论也只限提交材料的计算可行性与观察偏好，`statistical_guarantee=NONE`，不建立实际科研收益、统计等效或未来总体最优。

```text
python -m unittest tests.test_burden_decision -q
python scripts/check_burden_decision.py --output <新验收结果.json>
```

完整结果见[场景验收](../evidence/burden-decision-scenarios-20261002.json)与[工程验收](../evidence/burden-decision-20261002.json)。下一层现实证据应是在同一科学门槛下，以真实、完整计时和结算材料检查研究者工作是否减少；本轮代码与合成验收不代替该证据。

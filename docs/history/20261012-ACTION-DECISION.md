## 四种行动

| 行动 | 何时可建议 | 理由、有效期和下一步 |
| --- | --- | --- |
| 采用(限域) | 候选相对基线的同时下界超过冻结实用阈值；独立 v3 确认通过功效/完整性/费用/质量门槛，并满足本轮候选多重校正和至少 30 个确认族；按研究者损失比较后采用优于允许的替代行动 | 限于冻结任务、版本与输入范围；有效至研究者填写的时点。随后监测关键失败与分布漂移；最终接受仍由研究者决定 |
| 带护栏试用 | 有真实提交记录、证据完整且假设成立、在有效期内；已填写可执行护栏与正的试用暴露比例；损失比较倾向试用 | 说明护栏及其假定的残余伤害，不把假定视为已验证。补独立完整任务族以分辨实用增益阈值，或进行未参与筛选的确认 |
| 默认基线 | 未填写损失、证据不足、到期、护栏缺失，或按损失继续使用基线更合适 | 表示当前不改变工作方式，不表示候选无效。先补实际阻塞项，再考虑新增运行 |
| 不使用 | 研究者声明当前用途禁用，或有效的候选效用上界低于冻结最低效用 | 显示禁用/不适用的具体原因和有效期；条件改变时重新静态审阅或收集能改变该判断的证据，不写全球永久无用 |

每个候选输出所选行动，同时保留全部四种行动的可选状态、理由、状态损失、有效期和下一步；不只给一个推荐词。没有任何损失输入时，显示“默认基线 / LOSSES_REQUIRED”，仅本次规划有效，不编造截止日期或偏好值。

`valid_from`、`valid_until` 为带时区的明确日期；报告重算不延长有效期。版本、输入范围、损失、护栏改变立即要求复评。`now` 可由已有规划 API 注入以便重放测试。`automatic_execution=false`；多个候选各自可试用不等于授权同时开展多个试验。

## 研究者损失如何进入计算

[示例输入](../../examples/action-policy.json) 中的数值仅是演示，`researcher_id=EXAMPLE_NOT_REAL_PREFERENCES`。实际使用必须由研究者填写：

- `false_adoption_cost`：没有达到实用增益却采用的损失。
- `missed_use_cost`：达到实用增益却不使用的损失。
- `time_cost_per_hour`：每小时投入折合多少共同损失单位；不默认把时间换成美元。
- 每个候选的采用/试用/补证据小时数，试用获得收益的比例、残余误采用损失比例，以及具体护栏。
- 范围、有效期、最小实用增益、确认族数下限与收缩参数。

这些数值在 v2 协议中冻结并纳入哈希；同一采集历史不能事后改损失、候选或 seed 来伪装为原方案。偏好变化应留存原报告，另作明确的偏好敏感性解释；不要重写原始实验分配或用新损失反推旧研究“原本应该怎样”。

令 B 表示候选相对基线的总体效用差严格大于 `minimum_gain`。从同时区间投影得到 `Δ∈[L_candidate−U_baseline, U_candidate−L_baseline]`：下界过线只保留 B，上界不超过阈值只保留非 B，否则两者均保留。没有把置信度当成 B 的概率。

设 C_A 为误采用损失、C_M 为漏用损失、c 为每小时时间损失、h 为对应行动耗时、q 为研究者假定的试用残余伤害比例、e 为收益暴露比例：

| 行动 | 非 B 状态损失 | B 状态损失 |
| --- | --- | --- |
| 采用 | C_A + c·h_adopt | c·h_adopt |
| 试用 | q·C_A + c·h_trial | (1−e)·C_M + c·h_trial |
| 默认基线 / 不使用 | 0 | C_M |

先移除不符合证据、禁用或护栏条件的行动，再计算每个剩余行动相对于该状态下最小可行损失的差值；选择跨所有尚可能状态的最大后悔值最小者。精确并列优先基线。损失模型是研究者给定的决策简化，不是对真实经济效应或伤害概率的估计；不涵盖的损失应扩展模型，不能悄悄换算。

补证据优先级使用“当前可消除的后悔上限 − 补证据时间损失”，在冻结候选中选择最高者；同时给出对应行动与预算核验要求。计算这个上限时纳入证据补齐后才可能允许的采用行动，避免当前只能选基线就误报补证据价值为零；禁用候选的上限为零。它是无概率模型下的保守优先级，**不是估计的 EVSI，也不保证未来那一条观察最有价值**。完整性、过期、禁用等问题先修复；没有资格通过更多运行解决的问题不重复付费。现金预留仍走现有独立预算流程。卡片另外显示最坏状态损失；相对当前允许行动的零后悔不等于零损失。

## 多候选：同时区间、收缩与轮转

原引擎已经在每个候选每个本地样本数 n 上使用 `radius=sqrt(log(2KH/alpha)/(2n))`，K 为全部冻结候选（含基线），H 为每候选观察上限。联合界同时覆盖 K×H 个事件；新增名次输出复用这个矩形置信区域，不再对每一对候选单独做未经校正的检验。

对候选 i，名次区间为：

`best_rank = 1 + count(L_j > U_i)`；`worst_rank = K − count(U_j < L_i)`。

只要所有真实均值在同时区间内，所有真实排序也在这些区间内。相等与重叠允许多个位置；无观察为 [1,K]，假设失效或证据阻塞时不显示窄的有效名次。报告保持冻结候选顺序，不按噪声均值发布单一排行榜。关于名次同时区间的问题背景见 [Al Mohamad 等原始论文](https://arxiv.org/abs/1812.05507)；本实现使用现有有界均值区间的直接投影，没有实现该论文的 Tukey HSD 算法。

赢家诅咒处理采用所有候选共同的、采集前冻结的收缩：

`shrunk_mean = (n·raw_mean + strength·target)/(n+strength)`。

`target`、`strength`、理由均显式提交，不在看见赢家后拟合到最有利值。原始均值与收缩均值并列，收缩值**不用于缩窄置信界、确定名次或证据升级**。这是一种抑制极端观测的正则化措施，不是已证明消除所有选择偏差的无偏估计；真正采用还需独立确认。[van Zwet 与 Cator，2021](https://onlinelibrary.wiley.com/doi/abs/10.1111/stan.12241) 讨论了选择与收缩的理论背景；本实现不宣称复现其模型最优收缩。

`allocation=round_robin` 支持 3–32 个候选，示例为 **1 个基线 + 3 个候选完整方案**。每个独立输入单位都运行全部冻结候选，使用相同输入、独立会话；每 K 个单位为一轮，冻结 seed 决定随机起始排列，随后循环移位，每个候选在每个位置恰好一次。`execution_orders` 绑定每个单位顺序，记录必须提交 `execution_position`，缺失或不符即拒绝重算。

不满一轮的提前停止不宣称位置完全平衡。轮转不能自行消除携带效应；v2 额外要求明确声明 `no_order_or_carryover`，未知则暂停。它仍是提交声明，不能代替宿主隔离证据。每一完整批次预留全部候选费用；不能只补赢家、删失败或换候选后仍沿用原校正。

## 独立确认与实现接口

运行入口：[risk_acquisition.py](../../value_lab/risk_acquisition.py)、[行动计算](../../value_lab/action_decision.py)、[工作流与卡片](../../value_lab/workflow.py)。输入规则见 [JSON schema](../../schemas/risk-acquisition.schema.json)。

v2 的 `decision_policy` 与 `rotation_seed` 必填；v1 不接受它们，避免静默改变旧契约。可选 `confirmation_studies` 只接收原始 `suite/records/lock/cost_ledger` 包，调用既有任务选择与核心评估器重算；不接收 `passed=true`。还检查：

1. 完整候选方案、基线、任务和目录精确绑定；每候选最多一份本轮确认。
2. 确认确为 v3，目标为族等权质量，实用增益阈值覆盖行动阈值；不同效用目标先保持试用/基线，不能用质量确认冒充其他效用确认。
3. 确认 `alpha ≤ 本轮 alpha/(K−1)`，且此前已冻结；完整原功效门槛与 `max(30, 用户确认族数下限)` 都满足。
4. 筛选与确认的输入哈希、会话和族标识不得重叠；不因改名或原样复跑增加独立性。签名、哈希与本地锁本身不证明真实独立或事前注册。
5. 合成证据、失败、未知、缺成本、门槛未过均不能采用。原始文件验证在只读模式内进行，不借评估启动执行程序。

筛选阶段的同时比较与独立确认有各自的统计含义；不把两者的 α 宣传成新的未经推导的全系统错误率。输入来源和人类复核仍需实际核验；“采用(限域)”是供研究者决定的建议。

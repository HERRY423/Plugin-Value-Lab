# 可追溯的失败诊断

2026-09-29，源码版本保持 0.7.0。本轮将产物检查连回保留会话中的直接写入事件，并增加实际执行的组件替换实验。真人报告阅读验证按用户决定保留待完成。

## 产物谱系与证据上限

新建 native sidecar plan 带 `diagnostic_schema=pvl-trace-diagnosis-1`。每个检查指向声明的产物、收集摘要、会话中的 Write 调用及对应 tool_result 行号。必须精确匹配工作目录下的文件路径和内容字节，且有唯一、顺序正确的成功回执。只读事件不会成为生产者；缺流、字节不符、失败/重复回执、跨会话和后续可能修改文件的调用均保留 UNKNOWN。

这是 **L2.5：写入环节定位**。报告中的行号是事件文件行号，不是出错源码行。它证明保留宿主导出声明了该写入，不证明不存在未观测写入，也不证明该调用或某行代码是科学错误根因。Bash 脚本写文件、Edit 重建、多进程写入等尚无可信文件观察器时不靠命令文本猜测。

Skill 必须有成功回执和明确的 `parent_tool_use_id` 关联才能连接。仅在前面出现 Skill 或读取过 SKILL.md 都不足以补齐。父关联也不证明科学贡献。实际保留的 CSV 会话没有 Skill 调用，因此 Skill 仍为 UNKNOWN。受控 parent 字段测试单独标为合成传输测试。

旧回执保持原算法回放。可以另外生成新版视图，不改写原证据：

```powershell
python scripts/trace_diagnose.py --evidence <旧证据目录> --receipt-sha256 <原回执的规范JSON摘要> --output <全新报告目录>
```

报告链接回原始收集文件，搬迁时需同时保留原证据目录；新报告是视图，不是独立完整证据包。新建 sidecar 自动集成谱系并在原 manifest 中封存。

## 组件定位：真实重算

`component_localize.py` 对 2 或 3 个预声明文件组件运行全部 4 或 8 种候选/替换组合。冻结共同输入、程序入口、组件两种版本、对照、容差、答案和环境。每个案例/组合均调用已有科学执行器，在网络隔离沙箱中生成新产物；答案与评分器不进入子进程。执行次序预先随机化并保存，每次仅一次尝试。

```text
python scripts/component_localize.py --design <设计JSON> --sha256 <设计摘要> --inputs <公开文件目录> --submitted <冻结参考结果目录> --output <新目录> --runtime <既有Linux运行时>
```

设计格式为 `pvl-component-localization-1`：`components` 为 2/3 个 `{id,target,candidate:{path,sha256},replacement:{path,sha256}}`；`cases` 含目标和正常对照，每项为 `{id,role,manifest}`，manifest 采用已有 `pvl-science-execution-1`；`seed` 固定执行顺序。删除以替换成明确的空实现表达，其运行失败或缺输出不能算修复。

只比较其余位相同的相邻组合。程序完成、前后环境锁匹配、原失败消失、所有已声明输出通过、所有配对对照通过，才记 `LOCAL_REPLACEMENT_EFFECT`。两项缺陷交互时可出现“只有另一组件也已替换，当前替换才消除失败”。没有通过的比较保留 NOT_ESTABLISHED；缺运行保留 INCOMPLETE；不裁掉对照、不用重新评分冒充执行。

这建立局部文件配置的干预效果，不证明原生宿主实际激活了同名插件组件，也不是 L3 或真实研究总体因果效应。已有 prompt/tools/context 因子重评分保持其原始声明边界。

## 报告盲测与真人待完成

`diagnostic_review.prepare` 在调用前分别保存去标识报告包、作者构造答案键及摘要。Grok 使用新会话，只收报告，禁用工具、搜索和子代理。只计生产调用、Skill 父调用、组件替换三项的精确匹配；缺答仍进入分母。准确率仅限该小报告包，不外推到未见事故、独立科学标签或人的阅读能力。

保存原始最终回答、所请求模型、实际返回模型、会话/请求标识和用量。控制器测量的请求墙钟时间包括模型服务和回复时间，**不是人的阅读时间，也没有逐案例阅读计时**。真人定位准确率和阅读时间继续为 null，真人参与者数为 0。

## 未补足的宿主能力

隐藏访问仍依赖受控 Python 观察器；本轮未建立真实宿主普适文件访问监控。`backend_identity` 仍未纳入 native sidecar 原生判据；新增谱系不会把候选自报身份当作可信后端观察。L3 自动源码根因、自然使用修复收益、外部环境独立重建、真人易读性均未建立。

## 本轮实测结果

[机器证据](../evidence/trace-diagnostics-20260929.json) 记录：同一个公开 CSV canary 的两条历史真实宿主会话均连接到直接写入调用，其中一条 BH 检查失败；两个 Skill 父关联均为 UNKNOWN。两组件实验实际执行 8 次，三组件实际执行 16 次，分别得到 2 和 4 个条件性修复对比；格式组件未消除失败，三组件原始配置需要 method 与 selection 都修正。

实际 Grok Build 请求返回 `grok-4.7-build`，有效盲测 8/8 报告、24/24 定位字段符合调用前冻结的作者答案键；此小报告包不是独立总体样本。成功会话 `71c2a3e1-01f4-4e8e-a010-531f60fe2b50`，请求 `4ca5c1b2-5df0-4f9e-a373-c48ca9e4a34e`，请求墙钟 102.26 秒。首次请求被客户端截断/转存提示后取消，没有有效标签，35.22 秒；改用 `--verbatim` 发送同一冻结包后才成功，首轮记录没有删除。

本轮两次 Grok 返回费用合计约 $0.0751808；连同此前科学产物盲标，本任务记录约 $0.1424974。独立账户结算未知，没有付费 AgentMuxer 调用。完整本地回归 867 项通过、零跳过，镜像、接口冻结、插件结构检查通过，版本未增加。首次环境预检因系统 packaging 缺文件清单失败，也原样保留；它没有运行提交分析。

本轮未新增 CI 上传步骤，自动审批拒绝了尚未授权的外部产物上传目的地；本地验证和保留证据不受影响。

# 从模板创建转为研究人员与 Agent 协作设计

本次明确请求是对标 Claude Code 的语义访谈与推荐，减少研究人员填 verifier、路径、哈希和参数的负担。版本保持 0.7.0。新增的 `init --template / --proposal / --materials` 是本次授权范围内的接口变化，冻结清单只补这三项；不扩张 MCP 工具、运行时模块、评分器或主线文档。

## 创建时真正发生什么

1. **研究目标**：优先读取当前对话；只补问实际任务、可用结果/不可接受错误、可使用的脱敏材料。研究人员不需要先回答评分器或 JSON 配置问题。
2. **Agent 理解插件**：`init --plugin ... --goal ... --output NEW_BRIEF` 返回 `context.json`。它包含有路径和哈希的清单、技能正文与 README；源码只是待理解数据，不是执行指令。当前宿主 Agent 解释能力、机制和局限，并引用实际原文。
3. **推荐方案**：Agent 根据研究问题写真实正例、近邻反例和缺证据情境，解释为什么检验、什么结果有用、哪个失败重要。不会默认插入“2 + 2”。需要研究者判断的误差、参考可信度、独立重复等不由关键词模板猜测。
4. **机械装配**：Agent 写 `proposal.json`，运行 `init --plugin ... --proposal ... --materials ... --output NEW_STUDY`。编译器生成文件路径、结果 artifact ID、verifier、私有参考哈希、目录套件与中文研究方案。
5. **规则校准**：自动判据必须有正确与错误产物，使用真正的已有评分器检查；正确产物没通过、错误产物被放过、未获得判定，都在写入目标目录前阻断。人类判断保持具体 rubric 和真实评审需求，不生成假评审结果。
6. **审阅与修订**：研究人员阅读 `RESEARCH-PLAN.md`，用自然语言纠正任务、结果标准与证据边界；Agent 新建修订、再编译校准。首次真实试跑使用已有采集路径，遵守原有数据/运行预算授权，不把规则校准称作试跑。

语义理解发生在当前宿主 Agent，Python 是确定性编译器。独立终端没有 LLM 时会明确给出待 Agent 接手状态，不会谎称已经理解或推荐。当前实现没有另起付费模型、自动读取密钥或转发材料。它支持 Claude/Codex 等能够使用本地技能与 CLI 的宿主，而不是绑定一个新模型供应商。

## 研究人员看到什么

例如研究问题“插件是否真的改善分析结果，而不是靠高部分分数掩盖错误”，Agent 应推荐：

| 情境 | 研究人员需要判断 | Agent/编译器负责 |
| --- | --- | --- |
| 产物结构合法，但效应值错误 | 这种错误是否影响研究用途 | 结果判据与交付区分、失败产物校准 |
| 两组结果同样正确 | 相同结果是否意味着插件有增益 | 保留 WITH/WITHOUT，避免凭单组高分推荐 |
| 缺少独立供者信息 | 是否只能保留未知，需要补哪些材料 | 缺证据案例、纯决策规则与参考绑定 |

表格是设计示例，不是自动判定所有领域的通用真值。不同插件需要 Agent 实际读源、改变任务与检查方式；设计应解释选择理由，不是给每个插件换个名称。

## 支持范围

首批编译配方包括精确 JSON 结果、按实体比较数值表（明确绝对/相对误差）、允许/拒答决策，以及开放式人工评审。不新增评分器，不静默生成任意可执行 Python。完整 Agent 输入契约见 [技能参考](../../skills/assess-value/research-authoring.md)。复杂科研流程仍需 Agent 使用已有专用契约；不能因为配方不支持就把科学判断降级为字符串命中。

明确列举材料的角色与来源，限制数量和大小，拒绝越界/链接路径；私有参考或校准字节不能同时作为公开输入。编译产物中的 `evals/` 与 `private/` 归评估方，只有选定 `inputs/` 可进入被测 Agent；这与已有 OS 隔离机制配合，目录名本身不构成安全边界。

现有人工模板保留为 `init --template`，目录迁移与共享判据仍按原合同工作。默认入口的状态变化是有意的：没有 Agent 设计就不产出看似完整、实际全是占位符的 suite。初始问题未回答、真实条件未核对时，不进入正式冻结/采集。

## 验收与未验证项

软件测试覆盖上下文绑定、真实来源引用、三类情境、四种配方、正反校准、缺失材料/误差、私有材料泄露、修订锁失配、手工模板兼容和零观测边界。测试使用制造材料，不代表真实研究者访谈。

当前对话中的 Agent 可以用当前源码完成一次语义方案并编译，证明这条协作路径可走通；不能据此宣称所有宿主会自动选择技能、已经超过 Claude Code、真实作者耗时下降，或模型实际试跑成功。进一步体验验收应请非作者研究人员用自己的获准材料完成首次创建，记录追问次数、需人工改动的字段、首次校准失败原因与是否能解释最终判据；这些结果目前未知。

## 对标依据

[Claude Code 官方 plugin eval 文档](https://code.claude.com/docs/en/plugin-evals#create-your-first-eval-suite)描述了读取插件、访谈、推荐案例与评分、试跑、落盘的流程，也支持在已有会话里继续。PVL 本次补齐宿主 Agent 设计和自动编译校准，真实模型试跑仍单独保留证据与授权边界；不把本地校准充当已经完成同等的模型试跑。

# Implementation contract (v1)

Version 0.5.0 adds `replicate_effect` and `replicate-reference`: frozen `design`/`data` SHA-256 references, independent-unit design checks, bounded paired/blocked exact inference, full-family BH and leave-one-unit effect ranges. The result format is `pvl-replicate-result-1`; invalid/missing reference material remains unknown. See [the scientific contract](docs/REPLICATE-VERIFICATION.zh-CN.md). New references are included in replay preflight; design/data may be declared public Scenario inputs, while scorer answers remain separate.

Rigor extension (same product version): `verify-host-study` normalizes offline Codex/Claude evidence receipts; registering a recognized native plan verifies its archive and binds metadata to `suite_digest(plan.plugin_files)`. `de_table.testing_family` optionally commits a separate `{ids:[...]}` JSON reference; complete entity membership is checked before BH. All critical process checks must pass but never add outcome score. Optional `policy.decision_error_limits` requires both `unsupported_acceptance` and `over_refusal` in [0,1], complete paired error observations, and WITH rates within each split's frozen ceiling; missing rates block, violations cause regression. New bundles include a non-executable replay contract, while private scoring bytes remain external. `registry-replay-plan` inventories dependencies without execution; `registry-replay --expected-id --require-same-environment` pins identity and rejects runtime mismatch before scoring. Report differences and assessment completeness stay explicit. See [RIGOR.zh-CN.md](docs/RIGOR.zh-CN.md).

Same-version value indicators: `evaluate` adds `value_metrics` with fixed-denominator success uplift, rescue/harm counts and rates, task-kind strata, equal-family quality differences, run-level human/elapsed time and full cost per successful outcome. These are descriptive and cannot override global evidence, regression or synthetic gates. Optional frozen `policy.power_plan` validates `expected_family_sd`, `minimum_detectable_delta`, `alpha`, `power` and reports a prospective two-sided normal approximation for independent family-mean differences, never observed power or a new statistical verdict. Optional Boolean `policy.require_settled_costs` requires complete cost coverage plus unique base `cost.evidence_ref` and `basis: settled`, explicitly itemized settled supplemental cash or not-applicable coverage. `cost_analysis.cash_evidence` records gaps; settlement references are declarations, not invoice authentication, and labor stays timer-valued. HTML/Markdown render the new indicators; JSON retains full details. See [VALUE-METRICS.zh-CN.md](docs/VALUE-METRICS.zh-CN.md).

Same-version registry hardening: `register_study(..., parent=..., revision_reason=...)` supports actual evidence supplements under the unchanged frozen protocol/time/authors/plugin identity. Record-order-independent duplicate detection, symmetric session-overlap checks, one lineage per revision chain, superseded snapshots and inherited dissent prevent repeated observations or revisions becoming independent studies. `registry-export --with-reviews` creates `pvl-review-packet-1`; `registry-verify --expected-id` pins either packet or entry identity, and `registry-replay` accepts both formats while retaining dispute status. Reviews are staged before atomic publication. Ordinary snapshot exports explicitly exclude review history. No identity authentication, scientific replication or external adoption is inferred.

Same-product-version registry extension: `value_lab.corpus` validates public scenario releases and separately supplied committed answer keys. Grader `sealed` carries `verifier: {release_sha256, truth_sha256, case_id}` and binds `suite.corpus`; `evaluate` and `build_usage_card` accept explicit `corpus_root`. Answers never enter public suites. Reports add `corpus_errors` with planned denominators, unknowns, error bounds and WITH-minus-WITHOUT differences for unsupported acceptance and over-refusal, separately by development/heldout split. Synthetic releases stay synthetic. `value_lab.registry` provides register/view/review/export/verify/replay functions and CLI commands, with exclusive writes, immutable manifest-addressed study snapshots, source-engine fingerprints, session-overlap checks, exact-target dissent and declared replication comparability. No remote publication or identity authentication. Full proposed interchange and evidence limits: [REGISTRY.zh-CN.md](docs/REGISTRY.zh-CN.md). Product version is unchanged.

Artifact verification and Codex collection are same-version extensions. `artifact` rules read explicitly supplied, hash-bound files; `executable` rules additionally require a reviewed Python verifier hash and trusted verifier root. Core object-only calls leave these rules unresolved. Evaluation, usage cards and study comparisons can opt into local file verification through explicit keyword arguments or CLI flags. See [ARTIFACTS.md](docs/ARTIFACTS.md) for all scientific file contracts and failure semantics. h5ad verification has an optional `anndata` dependency; the core remains standard-library-only.

`prepare-codex` freezes plugin bytes, same-input snapshots and a counterbalanced schedule without model calls. `run-codex` executes that exact plan once and retains events, outputs, sessions, installation receipts and unknown costs. Requested conditions and installation are never promoted to observed conditions or plugin loading. See [CODEX.md](docs/CODEX.md). `link-decision-evidence` binds separate offline and host evidence without generating a pooled benefit claim; see [EVIDENCE-LAYERS.md](docs/EVIDENCE-LAYERS.md).

Research direction extension (same product version): `research_direction_advisor(action, context=None, before=None, after=None)` supports exactly `example` without inputs, `diagnose` with context, or `compare` with before/after contexts. Host Agent semantic reasoning is supplied through the `research-directions` skill; local deterministic validation does not browse, infer scientific truth or certify novelty. `research-plan CONTEXT --output DIR` writes a new plan; `research-example` emits synthetic context; `research-compare BEFORE AFTER --output FILE` preserves a revision comparison. HTTP routes: GET `/api/research/example`, POST `/api/research/diagnose`, POST `/api/research/compare`. Same loopback/Host/Origin/token limits apply. The seventh MCP tool has no external side effects; full schema and usage: [RESEARCH.zh-CN.md](docs/RESEARCH.zh-CN.md).

Same-version analysis extensions: graders may include `examples: [{output: str, passed: bool}]` for local calibration, never observations. `policy.require_cost_categories` optionally requires explicit supplemental cost coverage. `evaluate(..., cost_ledger=None)` and `build_usage_card(..., cost_ledger=None)` accept a version-1 ledger with category coverage and explicitly allocated additional/included expenses; reports/cards bind its digest. Optional `cost.basis` is estimate/settled/declared (legacy default declared). `inspect_rules(suite,samples=None)` performs rule diagnostics. `compare_studies(before,after)` takes each study's suite/records/lock and optional ledger/context; reports condition/task/rule changes, baseline and plugin-gain changes, and separate cost comparability. See [ANALYSIS.zh-CN.md](docs/ANALYSIS.zh-CN.md) for the complete input semantics and evidence limits. Current product version is 0.5.0; prior same-version revisions are retained.

Python 3.11+, standard library only; package `value_lab` at plugin root.

`suite.json`: object with `schema_version: 1`, `id`, `plugin: {name, version}`, `evidence_type: synthetic|local|external`, `runs_per_case` (1..50), `conditions: {model, host, tools, environment, budget}`, `policy: {min_quality_delta, quality_floor, max_case_regression, min_clusters, require_cost_saving, human_hourly_usd}`, `cases: [{id, cluster, kind: task|negative|abstention, prompt, graders: [{id, type: contains|not_contains|json_equals|human, value?, path?, rubric?, weight, critical, dimension: outcome|process}]}]`. Each case must have outcome graders. Human grader requires a rubric. Only outcome graders contribute quality. `conditions` must contain explicit nonempty strings except `tools` array and `budget` object. Freeze before collecting records; lock is consistency only, not independently witnessed preregistration.

`runs.jsonl`: one JSON object per planned (case_id, repetition, arm), with `arm: with|without`, `repetition` starts at 1; `suite_sha256`, globally unique `session_id`, `conditions` exactly matching suite, `plugin_loaded` bool consistent with arm, `status: completed|error|timeout|aborted|skipped`, `output` string, optional `error`; `cost: {model_usd: number|null, tool_usd: number|null, human_minutes: number|null}`, `duration_seconds: number|null`, `source: synthetic|manual|claude`, optional `reviews: {grader_id: {passed: bool|null, reviewer: string, rationale: string}}`. Human minutes may be supplied only from `human_intervals: [{actor, start, end}]` UTC ISO timestamps, no overlaps for an actor across records. Empty intervals explicitly prove only a declared zero human time, not external verification. Missing costs stay null. Native imports may have `import_issues: [string]`; these block evidence, not visibility. Native imports without output use `grades: {grader_id: {passed: bool|null, rationale: string}}` for outcome grading, require explicit mappings and keep evidence partial. Never synthesize observed conditions/sessions from suite expectations.

Core exports: `ValidationError`, `load_json(path)`, `write_json(path,obj)`, `suite_digest(suite)`, `validate_suite(suite)`, `evaluate(suite, records, lock=None) -> report`, `demo_suite()`, `demo_records(suite)`, `freeze(suite,path)` (exclusive lock), `load_records(path)`.

Scientific extension (no plugin version change): additional grader types `artifact_schema`, `numeric_tolerance`, `abstention_correct`, `over_refusal`, `backend_identity`, `exec`, and opaque `scenario` contracts. `evaluate` accepts explicit `artifact_root` and `verifier_root`; the latter holds scorer-only references and collector receipts. Artifact grader rules use `artifact` and `verifier`, never imported Boolean grades. `scenario` commits private criteria without revealing their types in the task suite. Reports add `scientific_errors` with full planned denominators, unresolved counts and missingness bounds. Critical process checks cannot silently disappear from comparability gates. See [complete contracts](docs/SCIENTIFIC-VALIDATION.md) and the [proposed Scenario Pack schema](schemas/science/scenario-pack.schema.json). Structural staging is not proof that a host lacks access to other filesystem paths.

Phase-two extension (same plugin version): `prepare-host-matrix`, `verify-codex-collection`, `registry-contrasts`, `registry-sign-review`, `registry-public`, and `registry-public-verify` are local-only commands. Reviews optionally add the exact `protocol` and Ed25519 `signature` contract in `schemas/registry/1/review.schema.json`; legacy reviews remain visible but cannot qualify positive public cards. Signed static summaries require separately trusted publisher/reviewer keys and explicit heldout declarations. No raw study material or private keys are automatically published. Host contrasts hold all non-host factors fixed; longitudinal alerts require one changing axis and strictly ordered, comparable observations. See [Phase 2](docs/PHASE2.md) for serialization, revocation, identity, freshness and scientific limits.

Report common fields: `schema_version`, `study_id`, `plugin`, `evidence_type`, `verdict`, `summary: {with_score, without_score, quality_delta, expected_runs, observed_runs, complete_pairs, clusters, cost_delta_usd, with_cost_usd, without_cost_usd}`, `blockers: [string]`, `warnings: [string]`, `cases: [{id, kind, cluster, with_score, without_score, delta, runs: [{arm,repetition,status,score,grades,cost_usd,issues}]}]`, `uncertainty`, `claim_limits`, `provenance`. Additional fields allowed. Scores/costs can be null.

Report module exports `write_reports(report, output_dir)` writing report.json, report.md, report.html. Static self-contained HTML; no external assets. Escape all user content; no innerHTML from evidence.

Local CLI: `python scripts/value_lab.py demo --output DIR`; `init --output DIR`; `freeze SUITE --lock LOCK`; `evaluate SUITE RECORDS --lock LOCK --output DIR [--gate]`; `export-claude SUITE --output DIR --plugin PATH`; `import-claude RESULT --suite SUITE --output RECORDS`; `plan-use CONTEXT --output DIR`; `usage-card SUITE RECORDS --lock LOCK --output DIR`; `doctor`; `serve`. The task-routing and usage-card interfaces are specified in [WORKFLOW-CONTRACT.md](docs/WORKFLOW-CONTRACT.md). Native module exports `export_claude(suite, output_dir, plugin_path)`, `import_claude(result,suite) -> records`, `build_command(plugin_path, output_dir, model, max_cost_usd, runs=3) -> list[str]` (planning only, never executes model calls). Native costs are estimates, no settlement assumption.

CLI gate: 0 only for complete non-synthetic positive local signal; 1 no gain/regression; 2 insufficient/simulation. No external/scientific benefit certification.

Execution/workbench (0.4): `workbench --data DIR [--port 8766] [--claude EXECUTABLE]` serves a loopback-only UI. `value_lab.execution.Engine` prepares frozen snapshots and launches one native Claude subprocess per explicitly authorized study. `prepare` performs no model calls. `start` binds authorization to `frozen_sha256`, verifies snapshot and executable hashes, refuses duplicate/running/unknown-interrupted execution, and preserves authorization plus process receipts. `stop` terminates the process tree where supported. Results, logs, errors, partial states and unknown costs persist. Restart never retries paid work. Native imports still use the conservative v1 evidence ceiling above; process launch is not a per-run session/load attestation. HTTP and lifecycle details: [WORKBENCH.zh-CN.md](docs/WORKBENCH.zh-CN.md). All seven MCP tools do not start models.

Optional `policy.objective`: `quality` (default) requires positive quality delta reaching min_quality_delta; `efficiency` requires non-decreasing mean quality, quality_floor, and strictly lower full cost. Both retain all critical and per-case regression gates. Efficiency evidence is descriptive, not a statistical noninferiority claim. Error/aborted records require `failure_kind: task` to be considered comparable; otherwise infrastructure or unclassified failure blocks value attribution. Completed records missing original output remain diagnostic regardless of imported Boolean grades.

Cost-dependent verdicts now require complete explicit supplemental cost coverage whenever the objective is `efficiency` or `require_cost_saving` is true, even if `require_cost_categories` was omitted. Positive public cards additionally require heldout outcomes themselves to meet the frozen objective, quality floor, critical and per-case regression gates. Development gains cannot substitute for heldout gains; cards retain separate split summaries and cost evidence. These are necessary local gates, not a statistical generalization guarantee.

The separate `prepare-claude-collection` / `run-claude-collection` / `verify-claude-collection` API supports read-only native JSON audit artifacts. It does not relax the older aggregate exporter's unsupported-grader rejection. See [native collection](docs/CLAUDE-COLLECTION.md). Release test acceptance rejects skipped or zero tests; registry cryptographic dependencies are installed in both CI and draft-release workflows.

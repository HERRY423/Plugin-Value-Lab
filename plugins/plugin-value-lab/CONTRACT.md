# Implementation contract (v1)

Online isolation revision (0.7.0): `prepare-native-session --sandbox` freezes an explicit runtime and fixed provider gateway. Native children have no direct network, host root or inherited credentials; only selected plugin bytes and result directories are mounted. The parent mediates bounded Anthropic Messages requests with its own key. Linux uses bubblewrap; the Windows implementation requires a local Windows engine and pinned Hyper-V container image, without a WSL/process fallback. Old masking plans cannot execute; offline recovery remains available. Real Linux kernel/fixture transport tests do not establish real LLM compatibility, Windows kernel acceptance or internal native-eval blinding. [Contract and evidence limits](docs/history/ONLINE-ISOLATION.zh-CN.md).

Research authoring revision (0.7.0): default `init` now emits an `AWAITING_AGENT_DESIGN` source/context handoff, not placeholder cases. The existing assess-value skill directs the current host Agent to interpret source-linked capabilities and research needs, recommend cases, and author `pvl-research-design-1`. `init --proposal --materials` compiles supported high-level assessment recipes, binds selected materials, and calibrates both positive and negative artifacts before writing a new study. Legacy scaffolding requires `--template`. The deterministic compiler does not claim LLM reasoning, a model pilot, scientific validity, or researcher usability. [Scope and evidence](docs/history/RESEARCH-AUTHORING.zh-CN.md).

Offline isolation/replay revision (product remains 0.7.0): the explicit developer utility `scripts/offline_eval.py` records supplied sanitized tool transcripts, serves pinned MCP cassettes, and runs selected public files through a Linux/WSL bubblewrap allowlist. Cassettes stay outside the child namespace; unknown calls, partial consumption, timeouts and missing isolation never fall back to a live backend. The original online masking profile was subsequently retired by the online revision above. Replay is contract evidence, never a new scientific execution. [Threat model, bounded scope exception and acceptance](docs/history/OFFLINE-ISOLATION-REPLAY.zh-CN.md).

Environment/recording revision: `record-live` is an explicitly selected live stdio tool proxy, distinct from offline replay. It publishes a cassette only after a bounded complete session and credential checks; public/de-identified data remains the caller's responsibility. PyDESeq2 reference runs automatically capture active dependency bytes and seal portable result artifacts. A supplied environment lock rejects drift before fitting; dependency-free artifact playback records no new scientific execution. Locks do not reconstruct environments or attest external system libraries/hardware. [Workflow and limitations](docs/history/ENVIRONMENT-RECORDING.zh-CN.md).

Metamorphic grader revision: `type: metamorphic` reads pinned prospective designs and collected numerical observations. Five reviewed relation families preserve entity coverage, input commitments, finite tolerances and missing-run denominators. Relation-only passes cannot establish task correctness, including inside private scenarios. No submitted code, network or LLM judge is executed. Source-registered extensions require parameter validation, transformation, comparison and mutation tests. [Scientific contracts and applicability](docs/history/METAMORPHIC-GRADERS.zh-CN.md).

Component methodology revision: complete randomized 2/3-factor plans regrade original outputs, preserving missing arms and configuration drift. Contrasts are descriptive, not authenticated component intervention or causal attribution. Prospective model-series diagnostics require invariant non-model suite content and continuous baseline correctness; they never remove cases. `equivalence` uses pinned paired independent-unit designs, feature-wise TOST with Bonferroni correction and mandatory individual deviation guards; zero-variance inference is unknown. Neither correlation nor failure to reject a difference establishes equivalence. [Usage and evidence limits](docs/history/COMPONENT-METHODOLOGY.zh-CN.md).

Outcome gate correction (product remains 0.7.0): each recomputed run now has `task_outcome`, separate from its weighted `score`. The shared success definition feeds value metrics, successful-cost denominators, scope/card recommendations and conditional guidance. Typed task evidence distinguishes decision, delivery and correctness; process graders remain unscored and cannot supply these roles. Required correctness failure cannot be averaged away; absent necessary evidence stays unknown. Optional frozen case `success_contract` declares version 1 and `mode: task|decision`, with additive grader-ID requirements. Text-only legacy suites remain labeled as configured checks, not semantic/scientific proof. Positive whole-suite guidance now additionally requires all WITH runs to satisfy task success; existing complete preregistered scopes remain assessed separately. [Exact semantics and adversarial acceptance cases](docs/history/OUTCOME-GATES.zh-CN.md).

Authoring revision (product remains 0.7.0): `load_suite` accepts canonical JSON, an explicit eval tree, or a project with a `pvl-evals-v1` pointer. `init` now creates one editable tree by default, with optional local plugin discovery and interactive task/rubric guidance. `--format json` retains JSON authoring. `suite-check` validates without executing graders; `suite-convert` resolves shared graders into a canonical suite or exports a fresh tree. SHA-256 locks still bind the resolved suite, never a pointer or an unexpanded reference. Missing metadata, conflicting sources, unsafe references and malformed frontmatter fail closed. [Format, examples and limitations](docs/history/AUTHORING.zh-CN.md).

Detection-boundary correction (product remains 0.6.0): `over_refusal` and `abstention_correct` assess the declared decision only; an absent/unsupported decision is unknown, and their receipts explicitly do not establish delivery, correctness or task success. Compose separate required artifact-schema and task-correctness graders. `artifact.labels` optionally accepts `aliases: {canonical: [aliases...]}`; mappings must be frozen, unambiguous and cannot redefine a canonical label. `artifact.json_fields` optionally accepts `unordered_paths: [expected-field-path...]` for unique string identity sets only; legacy fields remain ordered. ARI/NMI still measure partitions, not named-label correctness. Native diagnosis distinguishes Skill calls from reads of complete pinned candidate content; retained, hash-verified bytes permit newline-only text transport normalization. Reads do not establish execution or contribution. The seeded Python access observer is a bounded test instrument, not a production native-host leakage monitor. See [detector evidence](DETECTION-VALIDITY.md).

Version 0.5.0 adds `replicate_effect` and `replicate-reference`: frozen `design`/`data` SHA-256 references, independent-unit design checks, bounded paired/blocked exact inference, full-family BH and leave-one-unit effect ranges. The result format is `pvl-replicate-result-1`; invalid/missing reference material remains unknown. See [the scientific contract](docs/history/REPLICATE-VERIFICATION.zh-CN.md). New references are included in replay preflight; design/data may be declared public Scenario inputs, while scorer answers remain separate.

Rigor extension (same product version): `verify-host-study` normalizes offline Codex/Claude evidence receipts; registering a recognized native plan verifies its archive and binds metadata to `suite_digest(plan.plugin_files)`. `de_table.testing_family` optionally commits a separate `{ids:[...]}` JSON reference; complete entity membership is checked before BH. All critical process checks must pass but never add outcome score. Optional `policy.decision_error_limits` requires both `unsupported_acceptance` and `over_refusal` in [0,1], complete paired error observations, and WITH rates within each split's frozen ceiling; missing rates block, violations cause regression. New bundles include a non-executable replay contract, while private scoring bytes remain external. `registry-replay-plan` inventories dependencies without execution; `registry-replay --expected-id --require-same-environment` pins identity and rejects runtime mismatch before scoring. Report differences and assessment completeness stay explicit. See [RIGOR.zh-CN.md](docs/history/RIGOR.zh-CN.md).

Same-version value indicators: `evaluate` adds `value_metrics` with fixed-denominator success uplift, rescue/harm counts and rates, task-kind strata, equal-family quality differences, run-level human/elapsed time and full cost per successful outcome. These are descriptive and cannot override global evidence, regression or synthetic gates. Optional frozen `policy.power_plan` validates `expected_family_sd`, `minimum_detectable_delta`, `alpha`, `power` and reports a prospective two-sided normal approximation for independent family-mean differences, never observed power or a new statistical verdict. Optional Boolean `policy.require_settled_costs` requires complete cost coverage plus unique base `cost.evidence_ref` and `basis: settled`, explicitly itemized settled supplemental cash or not-applicable coverage. `cost_analysis.cash_evidence` records gaps; settlement references are declarations, not invoice authentication, and labor stays timer-valued. HTML/Markdown render the new indicators; JSON retains full details. See [VALUE-METRICS.zh-CN.md](docs/history/VALUE-METRICS.zh-CN.md).

Same-version registry hardening: `register_study(..., parent=..., revision_reason=...)` supports actual evidence supplements under the unchanged frozen protocol/time/authors/plugin identity. Record-order-independent duplicate detection, symmetric session-overlap checks, one lineage per revision chain, superseded snapshots and inherited dissent prevent repeated observations or revisions becoming independent studies. `registry-export --with-reviews` creates `pvl-review-packet-1`; `registry-verify --expected-id` pins either packet or entry identity, and `registry-replay` accepts both formats while retaining dispute status. Reviews are staged before atomic publication. Ordinary snapshot exports explicitly exclude review history. No identity authentication, scientific replication or external adoption is inferred.

Same-product-version registry extension: `value_lab.corpus` validates public scenario releases and separately supplied committed answer keys. Grader `sealed` carries `verifier: {release_sha256, truth_sha256, case_id}` and binds `suite.corpus`; `evaluate` and `build_usage_card` accept explicit `corpus_root`. Answers never enter public suites. Reports add `corpus_errors` with planned denominators, unknowns, error bounds and WITH-minus-WITHOUT differences for unsupported acceptance and over-refusal, separately by development/heldout split. Synthetic releases stay synthetic. `value_lab.registry` provides register/view/review/export/verify/replay functions and CLI commands, with exclusive writes, immutable manifest-addressed study snapshots, source-engine fingerprints, session-overlap checks, exact-target dissent and declared replication comparability. No remote publication or identity authentication. Full proposed interchange and evidence limits: [REGISTRY.zh-CN.md](docs/history/REGISTRY.zh-CN.md). Product version is unchanged.

Artifact verification and Codex collection are same-version extensions. `artifact` rules read explicitly supplied, hash-bound files; `executable` rules additionally require a reviewed Python verifier hash and trusted verifier root. Core object-only calls leave these rules unresolved. Evaluation, usage cards and study comparisons can opt into local file verification through explicit keyword arguments or CLI flags. See [ARTIFACTS.md](docs/history/ARTIFACTS.md) for all scientific file contracts and failure semantics. h5ad verification has an optional `anndata` dependency; the core remains standard-library-only.

MCP artifact handoff repair (0.8.0): the existing evaluation and usage-card tools accept optional `artifact_root` / `verifier_root` selectors confined to startup-authorized `PVL_ARTIFACT_ROOT` / `PVL_VERIFIER_ROOT`. Omitted selectors use configured roots; no configuration retains object-only behavior. Roots must be separate and non-overlapping. Both tools recompute from actual files and retained hashes; usage cards include per-grade `source.verification_receipts` from that evaluation. MCP program execution (`executable`, `exec`, including scenario children) is always unresolved. CLI execution semantics and scientific evidence ceilings are unchanged. See the controlled handoff section in [ARTIFACTS.md](docs/history/ARTIFACTS.md).

Task selection increment (0.8.0): optional `context.task_selection` on the existing planner compares scoped stage capabilities and complete task plans with native/script/workflow alternatives. `value_lab.task_selection` enumerates a bounded catalog and recomputes fully bound raw paired studies through the existing evaluator; it never accepts cached success cards. Exact task/catalog/plan/input/component bindings, complete costs, stage and integration checks, frozen regression limits and unresolved alternatives govern selection. The objective minimizes distinct new plugins, then all plugins; no cost-saving or generalized benefit claim follows. The planner MCP adds host-confined material selectors and `plan-use` adds `--artifacts` / `--verifiers`. Planning always disables program execution. Full contract and explicit limitations: [task selection](docs/history/TASK-SELECTION.zh-CN.md).

Prospective evidence acquisition increment (0.8.0): `context.evidence_acquisition` binds a mother protocol, its separately retained digest and an append-only batch history. The deterministic frontier/cost rule selects only potentially decision-changing checks; each proposed batch freezes its complete matrix, budget cap and preceding history. Screening affects only the shortlist and uses input snapshots/cases disjoint from reserved whole-task confirmation. No started rows are removed, unknown costs reserve the cap and halt new batches, confirmation closes screening, and stopping never implies success. No new CLI/MCP signature, autonomous execution/payment, population error control or real-world efficiency claim is introduced.

Evidence bridge increment (0.8.0): `context.evidence_bridge` alongside an empty target `task_selection` compares an independently committed source selection against a new target under the reviewed `pvl-paired-matrix-bridge-1` contract. Same-scope replay, verified input-content equivalence, target-data/environment bridging and new-study barriers remain distinct. Actual matrix bytes qualify only narrowly input-derived count/sample/identity reference updates; arbitrary answer or threshold changes cannot be waived. A supported old plan and its original paired comparator produce one separately frozen full-target protocol, with fresh target records, complete costs and actual file verification. Source sessions/artifact paths cannot stand in for new target observations. No old adoption claim transfers, and existing exact-scope citation/conditional-guidance checks remain unchanged.

`prepare-codex` freezes plugin bytes, same-input snapshots and a counterbalanced schedule without model calls. `run-codex` executes that exact plan once and retains events, outputs, sessions, installation receipts and unknown costs. Requested conditions and installation are never promoted to observed conditions or plugin loading. See [CODEX.md](docs/history/CODEX.md). `link-decision-evidence` binds separate offline and host evidence without generating a pooled benefit claim; see [EVIDENCE-LAYERS.md](docs/history/EVIDENCE-LAYERS.md).

Research direction extension (same product version): `research_direction_advisor(action, context=None, before=None, after=None)` supports exactly `example` without inputs, `diagnose` with context, or `compare` with before/after contexts. Host Agent semantic reasoning is supplied through the `research-directions` skill; local deterministic validation does not browse, infer scientific truth or certify novelty. `research-plan CONTEXT --output DIR` writes a new plan; `research-example` emits synthetic context; `research-compare BEFORE AFTER --output FILE` preserves a revision comparison. HTTP routes: GET `/api/research/example`, POST `/api/research/diagnose`, POST `/api/research/compare`. Same loopback/Host/Origin/token limits apply. The seventh MCP tool has no external side effects; full schema and usage: [RESEARCH.zh-CN.md](docs/history/RESEARCH.zh-CN.md).

Same-version analysis extensions: graders may include `examples: [{output: str, passed: bool}]` for local calibration, never observations. `policy.require_cost_categories` optionally requires explicit supplemental cost coverage. `evaluate(..., cost_ledger=None)` and `build_usage_card(..., cost_ledger=None)` accept a version-1 ledger with category coverage and explicitly allocated additional/included expenses; reports/cards bind its digest. Optional `cost.basis` is estimate/settled/declared (legacy default declared). `inspect_rules(suite,samples=None)` performs rule diagnostics. `compare_studies(before,after)` takes each study's suite/records/lock and optional ledger/context; reports condition/task/rule changes, baseline and plugin-gain changes, and separate cost comparability. See [ANALYSIS.zh-CN.md](docs/history/ANALYSIS.zh-CN.md) for the complete input semantics and evidence limits. Current product version is 0.6.0; prior same-version revisions are retained.

Python 3.11+, standard library only; package `value_lab` at plugin root.

`suite.json`: object with `schema_version: 1`, `id`, `plugin: {name, version}`, `evidence_type: synthetic|local|external`, `runs_per_case` (1..50), `conditions: {model, host, tools, environment, budget}`, `policy: {min_quality_delta, quality_floor, max_case_regression, min_clusters, require_cost_saving, human_hourly_usd}`, `cases: [{id, cluster, kind: task|negative|abstention, prompt, graders: [{id, type: contains|not_contains|json_equals|human, value?, path?, rubric?, weight, critical, dimension: outcome|process}]}]`. Each case must have outcome graders. Human grader requires a rubric. Only outcome graders contribute quality. `conditions` must contain explicit nonempty strings except `tools` array and `budget` object. Freeze before collecting records; lock is consistency only, not independently witnessed preregistration.

`runs.jsonl`: one JSON object per planned (case_id, repetition, arm), with `arm: with|without`, `repetition` starts at 1; `suite_sha256`, globally unique `session_id`, `conditions` exactly matching suite, `plugin_loaded` bool consistent with arm, `status: completed|error|timeout|aborted|skipped`, `output` string, optional `error`; `cost: {model_usd: number|null, tool_usd: number|null, human_minutes: number|null}`, `duration_seconds: number|null`, `source: synthetic|manual|claude`, optional `reviews: {grader_id: {passed: bool|null, reviewer: string, rationale: string}}`. Human minutes may be supplied only from `human_intervals: [{actor, start, end}]` UTC ISO timestamps, no overlaps for an actor across records. Empty intervals explicitly prove only a declared zero human time, not external verification. Missing costs stay null. Native imports may have `import_issues: [string]`; these block evidence, not visibility. Native imports without output use `grades: {grader_id: {passed: bool|null, rationale: string}}` for outcome grading, require explicit mappings and keep evidence partial. Never synthesize observed conditions/sessions from suite expectations.

Core exports: `ValidationError`, `load_json(path)`, `write_json(path,obj)`, `suite_digest(suite)`, `validate_suite(suite)`, `evaluate(suite, records, lock=None) -> report`, `demo_suite()`, `demo_records(suite)`, `freeze(suite,path)` (exclusive lock), `load_records(path)`.

Scientific extension (no plugin version change): additional grader types `artifact_schema`, `numeric_tolerance`, `abstention_correct`, `over_refusal`, `backend_identity`, `exec`, and opaque `scenario` contracts. `evaluate` accepts explicit `artifact_root` and `verifier_root`; the latter holds scorer-only references and collector receipts. Artifact grader rules use `artifact` and `verifier`, never imported Boolean grades. `scenario` commits private criteria without revealing their types in the task suite. Reports add `scientific_errors` with full planned denominators, unresolved counts and missingness bounds. Critical process checks cannot silently disappear from comparability gates. See [complete contracts](docs/history/SCIENTIFIC-VALIDATION.md) and the [proposed Scenario Pack schema](schemas/science/scenario-pack.schema.json). Structural staging is not proof that a host lacks access to other filesystem paths.

Phase-two extension (same plugin version): `prepare-host-matrix`, `verify-codex-collection`, `registry-contrasts`, `registry-sign-review`, `registry-public`, and `registry-public-verify` are local-only commands. Reviews optionally add the exact `protocol` and Ed25519 `signature` contract in `schemas/registry/1/review.schema.json`; legacy reviews remain visible but cannot qualify positive public cards. Signed static summaries require separately trusted publisher/reviewer keys and explicit heldout declarations. No raw study material or private keys are automatically published. Host contrasts hold all non-host factors fixed; longitudinal alerts require one changing axis and strictly ordered, comparable observations. See [Phase 2](docs/history/PHASE2.md) for serialization, revocation, identity, freshness and scientific limits.

Report common fields: `schema_version`, `study_id`, `plugin`, `evidence_type`, `verdict`, `summary: {with_score, without_score, quality_delta, expected_runs, observed_runs, complete_pairs, clusters, cost_delta_usd, with_cost_usd, without_cost_usd}`, `blockers: [string]`, `warnings: [string]`, `cases: [{id, kind, cluster, with_score, without_score, delta, runs: [{arm,repetition,status,score,grades,cost_usd,issues}]}]`, `uncertainty`, `claim_limits`, `provenance`. Additional fields allowed. Scores/costs can be null.

Report module exports `write_reports(report, output_dir)` writing report.json, report.md, report.html. Static self-contained HTML; no external assets. Escape all user content; no innerHTML from evidence.

Local CLI: `python scripts/value_lab.py demo --output DIR`; `init --output DIR`; `freeze SUITE --lock LOCK`; `evaluate SUITE RECORDS --lock LOCK --output DIR [--gate]`; `export-claude SUITE --output DIR --plugin PATH`; `import-claude RESULT --suite SUITE --output RECORDS`; `plan-use CONTEXT --output DIR`; `usage-card SUITE RECORDS --lock LOCK --output DIR`; `doctor`; `serve`. The task-routing and usage-card interfaces are specified in [WORKFLOW-CONTRACT.md](docs/history/WORKFLOW-CONTRACT.md). Native module exports `export_claude(suite, output_dir, plugin_path)`, `import_claude(result,suite) -> records`, `build_command(plugin_path, output_dir, model, max_cost_usd, runs=3) -> list[str]` (planning only, never executes model calls). Native costs are estimates, no settlement assumption.

CLI gate: 0 only for complete non-synthetic positive local signal; 1 no gain/regression; 2 insufficient/simulation. No external/scientific benefit certification.

Execution/workbench (0.4): `workbench --data DIR [--port 8766] [--claude EXECUTABLE]` serves a loopback-only UI. `value_lab.execution.Engine` prepares frozen snapshots and launches one native Claude subprocess per explicitly authorized study. `prepare` performs no model calls. `start` binds authorization to `frozen_sha256`, verifies snapshot and executable hashes, refuses duplicate/running/unknown-interrupted execution, and preserves authorization plus process receipts. `stop` terminates the process tree where supported. Results, logs, errors, partial states and unknown costs persist. Restart never retries paid work. Native imports still use the conservative v1 evidence ceiling above; process launch is not a per-run session/load attestation. HTTP and lifecycle details: [WORKBENCH.zh-CN.md](docs/history/WORKBENCH.zh-CN.md). The six default MCP tools and optional research tool do not start models.

Optional `policy.objective`: `quality` (default) requires positive quality delta reaching min_quality_delta; `efficiency` requires non-decreasing mean quality, quality_floor, and strictly lower full cost. Both retain all critical and per-case regression gates. Efficiency evidence is descriptive, not a statistical noninferiority claim. Error/aborted records require `failure_kind: task` to be considered comparable; otherwise infrastructure or unclassified failure blocks value attribution. Completed records missing original output remain diagnostic regardless of imported Boolean grades.

Cost-dependent verdicts now require complete explicit supplemental cost coverage whenever the objective is `efficiency` or `require_cost_saving` is true, even if `require_cost_categories` was omitted. Positive public cards additionally require heldout outcomes themselves to meet the frozen objective, quality floor, critical and per-case regression gates. Development gains cannot substitute for heldout gains; cards retain separate split summaries and cost evidence. These are necessary local gates, not a statistical generalization guarantee.

The separate `prepare-claude-collection` / `run-claude-collection` / `verify-claude-collection` API supports read-only native JSON audit artifacts. It does not relax the older aggregate exporter's unsupported-grader rejection. See [native collection](docs/history/CLAUDE-COLLECTION.md). Release test acceptance rejects skipped or zero tests; registry cryptographic dependencies are installed in both CI and draft-release workflows.

# 宿主能力契约与可恢复增量采集

本轮将“这个宿主是否受支持”细化为“这份材料能够支持哪些具体结论”。核心消费者只读取版本化的能力语义和证据状态，不根据宿主名称猜测字段含义。目前资格包仍只覆盖 Codex Desktop `codex_work_desktop`、引擎 `0.159.2`；没有由此新增其他宿主或版本的资格声明。

## 逐结论处理

`host_capabilities.py` 定义统一词汇、校验器、逐结论依赖解析和差异比较。`context_stream.py` 是具体适配器；以后新增适配器应在边界映射这些语义，不能往核心判定中增加宿主分支。

| 能力 | 本适配器能够支持的内容 | 不能据此推断 |
| --- | --- | --- |
| 会话、请求、模型身份 | 本地元数据及响应／轮次绑定，逐项给出来源 | 服务商认证、插件字节或独立执行真实性 |
| 请求用量 | 输入含缓存；缺字段仍为 null | 再加一遍缓存、用输出或累计量补输入 |
| 上下文采样 | 匹配响应后的输入加输出采样值 | 连续实时占用、累计费用 |
| 三种累计账本 | 线程、轮次、上下文流分别保留 | 相互替代、除以上下文容量、推导美元结算 |
| 本地恢复 | 完整事件边界、前缀、解析器和文件身份绑定 | 远端任务已经完成或已经结算 |
| 产物访问、工具声明／加载／调用、插件身份、比较执行、实际费用、远端状态 | 本日志适配器明确 `NOT_PROVIDED` | 从对话文字、成功 CSV 检查或 token 数补齐 |

每项能力包含固定 `semantic_id`、`status`、值、来源引用和原因。`OBSERVED` 只代表本地材料可支持相应语义；`UNKNOWN` 代表本应可采集但缺失／不匹配；`UNSUPPORTED` 代表宿主字段语义尚未通过资格验证；`NOT_PROVIDED` 代表该适配器不提供。后三种状态的值必须为 null，不接受默认零或上次值回填。

`resolve_requirements(snapshot, claims)` 逐项核对调用方要求的精确语义。例如请求输入存在而上下文事件缺失时，请求用量可以可用，上下文仍未知；要求另一版本语义时不能仅凭同名字段通过。返回 `LOCAL_EVIDENCE_AVAILABLE` 不表示科学正确、采用建议或执行授权。

旧版 `codex_context.capture()` 保持原快照格式。新增契约不会传入文件评分器改变其结论；未通过资格验证的宿主仍可独立验证授权目录下已有 CSV，CSV 通过也不会改变宿主事实。MCP 的授权根目录与禁止执行提交程序的边界保持原样。

## 增量游标及恢复

首次运行：

```text
python scripts/collect_codex_context.py --rollout <明确授权的日志.jsonl> --session-id <会话ID> --incremental --output <新目录/批次1>
```

日志追加后：

```text
python scripts/collect_codex_context.py --rollout <同一日志.jsonl> --session-id <同一会话ID> --incremental --previous <批次1> --output <新目录/批次2>
```

每个不可覆盖的交付目录同时保存：

- `checkpoint.json`：完整事件偏移、行号、前缀摘要、文件身份、解析器版本与源码身份、会话、压缩阶段、待匹配响应、去重身份及账本状态。
- `report.json`：本批新响应身份、原响应更新、能力快照、逐结论状态、来源摘要及读取／解析负担。
- `COMMITTED.json`：整份交付完成与字节校验标记；没有标记的暂存目录不能恢复为已完成结果。

半条 JSON 或 UTF-8 字符不会进入游标。追加完整后只解析新增的完整事件；先前待匹配的响应可以产生 `sample_upserts`，这表示同一响应的后续解释，不是新增独立观察。合并报告必须按 `response_id` 更新并保留父修订，不得把各批的快照或 upsert 数量相加。`new_response_count` 统计本地新增响应身份，包含后来可能识别为压缩或未绑定的响应，不能当作科研样本量。

不变日志续读的新增响应数和解析事件数均为零。相同源／父批次／输出请求可以幂等恢复；写入中断后保留原提交与失败暂存材料，显式添加 `--resume-publication` 完成重新交付。输出已有其他内容时拒绝覆盖。返回 `INCOMPLETE` 的内容尚未提交，不能作为下一次 `--previous`。

## 不以放宽上限替代增量设计

单次新增读取默认最多 64 MiB，可用 `--max-new-bytes` 调低；总日志可以超过旧快照入口的 64 MiB 上限。单个事件最多 2 MiB，超大事件或不足以容纳事件的批量预算会明确报错，不截断成有效记录。

**增量解析不等于只读取新增字节。** 对可被改写的普通本地文件，要保证任意旧前缀改动都能被发现，就必须重读并校验该前缀。本实现流式校验历史前缀，并再次核对本次确认的前缀与文件身份；旧事件不再次 JSON 解析。报告分别给出 `new_bytes_parsed` 与 `prefix_bytes_rehashed`，不将线性校验 I/O 隐藏为常数成本。

读取缓冲有界；游标中的响应去重集合随响应数增长，并非固定大小。checkpoint 不保存对话正文或源文件绝对路径，但会话／模型标签、用量与来源身份仍可能敏感，应作为私有材料保存。本实现不提供删除策略、共享授权或自动上传。

## 升级、损坏与回退

| 情况 | 行为 |
| --- | --- |
| 同文件正常追加 | 校验旧前缀，解析新增完整事件 |
| 文件截断或完整前缀改写 | 拒绝旧游标，保留已有交付 |
| 日志轮转，即使新文件字节完全相同 | 文件身份不同，拒绝复用 |
| 读取期间文件发生变化 | 本次不提交；稍后核实原文件再继续 |
| 解析器源码／版本或契约变化 | `PARSER_CHANGED`，不默默迁移旧内部状态 |
| 未通过资格验证的新宿主版本 | 相关测量 `UNSUPPORTED`；本地续读与独立产物检查不被提升或抹除 |
| 未提交或损坏的 checkpoint | 拒绝恢复，不从聊天摘要猜测 |

升级流程应保留旧包与旧报告，先对异常样本、字段语义和升级差异进行资格验证，再在新目录重放原日志建立新谱系。不能仅修改版本白名单，或把相似字段名视为兼容证明。`compare_capabilities` 显示逐项事实变化和资格变化，不自动宣布全工具失效。文件摘要只证明本地内容绑定；无法防止能同时修改源文件、checkpoint 和所有摘要的主体伪造历史。

冻结兼容样本 `tests/fixtures/codex-context-v1.json` 在本轮重构之前由旧代码生成，保留其源码摘要和完整原输出，覆盖正常、部分尾部、未通过资格验证版本与压缩场景。新测试另外覆盖逐事件断点、跨批次去重／更新、日志轮转、保持大小与时间戳的前缀篡改、并发变化、交付中断、字段语义变化和独立 CSV 检查。

```text
python -m unittest tests.test_codex_context tests.test_context_stream -q
python scripts/check_context_contract.py --output <新验收报告.json>
```

第二条命令只制造本地合成日志，验证大于 64 MiB 的日志按批次处理，不启动模型或读取真实私有会话。完整资格范围和校验结果见[工程验收记录](../evidence/host-capabilities-20261002.json)。合成故障演练、旧报告兼容与分发包检查均不等于新宿主实测、服务商认证、真实科研收益或发布资格。

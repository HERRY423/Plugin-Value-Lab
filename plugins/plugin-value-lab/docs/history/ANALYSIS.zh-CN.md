# 评分、变化比较与成本分析

这次增强保持产品版本 **0.4.0-alpha.1**，没有升级版本号。主要入口仍是本地评估工作台。

## 评分规则：冻结前验证能否回答问题

每个任务可以添加多条规则，分别设置权重、结果/过程分类和关键门槛。结构校验会拒绝空判据、未知字段、重复规则、同一输出要求同时包含和禁止其子串、同一个 JSON 路径的互斥目标、无效路径、非有限数值和权重溢出。重复规则即使更换名称或权重也会被拦截。子串包含关系、重复任务提示和缺少正反校准样例会产生提示。

展开“校准样例”填入**应该通过**和**应该失败**的输出。确定性规则与校准标签不符时不能冻结。标签是设计者的预期，不是外部评审。人工规则无法由这些样例变成已完成人工审阅；界面中的试评分会保留待审状态。

“试评分文本”只运行本地判据，不调用模型，不写入实测账本。页面显示每条判据是否通过、加权结果和关键失败，帮助识别“有关键词但答案错误”的宽松规则。文字检查本身不能证明语义正确或插件未被触发。

结果规则决定质量；过程规则只作执行诊断。兼容既有的关键过程规则：它不贡献质量得分，只限制对应案例的使用卡推荐。要让错误答案触发整体质量门槛，应使用关键结果规则。JSON 精确判定支持本地记录评估，Claude 原生导出没有等价判据时仍然拒绝执行准备，不降级为关键词评分。

## 插件版本与模型变化：先核对条件，再比较分数

在一项研究中点“以此方案准备版本 / 模型对照”，会复制任务、判据、权重、校准样例、运行条件、预算与政策。修改插件目录或模型后重新冻结，旧研究保持原样。复制的是方案，不复制实测输出，也不自动执行新任务。

在“比较两项评估”选择原研究和新研究。系统重新读取原始记录并计算结果，不相信预先写好的分数。比较包括：

- 插件身份、版本和内容指纹。即使版本标签相同，文件内容变动也会被识别。
- 模型、宿主、工具、环境、执行预算、重复次数、质量与成本政策，以及已记录的 Claude 执行器版本。
- 任务增删、提示、任务类别、评分类型/权重/关键标记/校准样例变化。
- 原始文件和成本修订的完整性，以及两项研究是否复用会话身份。

只改变插件时，可以观察固定模型下的插件变化；只改变模型时，可以观察固定插件下的模型变化。**同时改变插件和模型时，页面仍展示诊断数值，但禁止单因素归因。** 任务或规则变更的行不会计算变化差值；整体任务集变化时也不只挑交集计算总平均。

页面同时呈现三种数值：有插件得分变化、无插件基线变化、插件贡献变化。最后一项为“新研究的有/无插件差值减去原研究的差值”，用于避免把模型整体变强误称为插件改进。它是描述性比较，不是自动成立的因果估计。模型别名、服务路由和时间变化仍可能影响结果，系统不伪造实际模型快照。

缺少插件内容指纹、来源文件被改动、观察不足或条件混杂时，比较结果是 `NOT_COMPARABLE`；模拟输入始终是 `SIMULATION_ONLY`。可比不等于新版本更好，更不自动授权升级、扩权或替换插件。

## 成本：把已知、未知和重复核算分开

原始单次记录仍有模型费用、工具费用、人工分钟和原始计时。可选 `cost.basis` 为 `estimate`（估计）、`settled`（声明已结算）或 `declared`（声明，旧记录默认）。人工时间按冻结时薪折算，单独归入声明价值，不伪装成已结算账单。

新增补充账本包含模型、工具、人工、评分模型、准备/设置、重试和其他开销。每项必须有独立标识与凭据明细行引用，并说明：

| 字段 | 含义 |
|---|---|
| `amount_usd` | 有限非负美元金额；`null` 是未知 |
| `basis` | 估计、声明已结算或人工声明 |
| `treatment` | `additional` 加入总额；`included` 已包含，仅保留明细 |
| `arm` | 有插件、无插件或共同成本 |
| `with_fraction` | 共同成本分给有插件组的比例，必须明确提供 |
| `case_id` / `repetition` | 可选的精确分配范围；省略则按对应组的全部计划执行均摊 |
| `human_intervals` | 补充人工费用必需；原始操作者、带时区开始和结束时间 |

账本的 `coverage` 分别确认评分、准备、重试和其他成本是未知、已包含、不适用，还是已列明。声明“已包含”后再新增同类别费用、重复凭据行、超范围分配和人工计时重叠会被拒绝或阻断。人工补充金额必须与计时和冻结时薪一致；不能和原记录重复计算。

**原生整批费用估计单独展示，不再叠加进逐次费用。** 原生估计可能已经包含评分调用。预算核对只比较原生估计与原生额度，不能把这个额度冒充全部人工、工具投入的硬上限。

完整分析提供已知小计、类别完整后的总额、每次计划执行成本、每次成功成本、失败次数、人工分钟、已提交 Token 计数、时长中位数/P90，以及不同人工时薪下的敏感性。成功指达到冻结质量下限且关键结果规则通过；费用分子保留失败开销。没有成功或金额不完整时，单位成功成本保持未知。

新建工作台方案默认冻结 `policy.require_cost_categories=true`，未确认额外成本类别时不能给出完整增益结论。旧方案保持既有政策；其旧平均费用仍是已提交记录口径，完整成本面板不会据此宣称类别已覆盖。敏感性分析不改写冻结政策或原判定。

保存成本时写入 `analyses/<修订ID>/`：新账本、报告、使用卡和绑定来源文件哈希的清单。旧输出不变。页面主结论、成本表及后续研究比较使用最新修订；原始报告仍可下载。哈希与凭据引用只支持本地核对，不认证费用真实性或独立评审。

## CLI 与 MCP

```text
python scripts/value_lab.py check-rules suite.json --samples samples.json --output scoring-check.json
python scripts/value_lab.py evaluate suite.json runs.jsonl --lock protocol.lock.json --cost-ledger cost-ledger.json --output revised-report
python scripts/value_lab.py usage-card suite.json runs.jsonl --lock protocol.lock.json --cost-ledger cost-ledger.json --output revised-card
python scripts/value_lab.py compare-studies before.json after.json --output comparison.json
```

比较文件各包含 `suite`、`records`、`lock`，可选 `cost_ledger` 与 `context`（`plugin_sha256`、`claude_version`、`integrity_issues`）。直接提交的上下文仍是声明；工作台从本地快照和清单读取这些字段。

原有六个评估与使用指导 MCP 工具保持兼容（研究方向扩展另增第七个工具）：`validate_value_suite` 新增可选 `samples`，返回规则警告和试评分；`evaluate_plugin_value` 与 `build_plugin_usage_card` 新增可选 `cost_ledger`。研究比较通过工作台或 CLI 完成。所有分析功能只处理已提供材料，不启动付费评估、不拉取价格、不改账户状态。

软件测试和浏览器验收使用制造的记录；不能当成真实插件收益、真实费用或独立研究结果。

# 三个结构性风险：本次收缩与验收边界

本页记录 0.4.0-alpha.1 阶段的结构修复，现已包含在 0.5.0 中。产品首先服务正在修复插件的作者：从已有配对记录定位问题，再准备可比较的复测。登记处是可选的本地证据账本，交换格式仍是暂定格式。

## 1. 安装动机：先交付可用的改进清单

作者不必为了获取帮助先公开评分、申请认证或加入登记处。现有 `usage-card` 和工作台现在直接生成：

- 定位到任务、WITH/WITHOUT 组、重复次序和判据的诊断清单；执行问题和证据缺口优先，关键结果其次。两组均保留，失败基础设施不冒充插件缺陷。
- 已失败和未知结果分开；整项研究阻断继续可见。提示只帮助排查，不把相关性写成根因。
- 保留原阈值、任务集合、负面对照和两组重复次数的复测计划。插件改动用内容摘要区分，无需增加版本号；不自动启动任何模型调用。
- 现有 `compare-studies` 和工作台复制方案入口检查修复前后的可比性。不能只重跑成功案例、删失败或放宽判据来制造收益；开发任务的复测不代表未见任务的泛化。

离线体验，无需安装到宿主或登记：

```sh
python scripts/value_lab.py demo --output work/author-demo
python scripts/value_lab.py usage-card work/author-demo/suite.json work/author-demo/runs.jsonl --lock work/author-demo/protocol.lock.json --output work/author-card
```

阅读 `work/author-card/USAGE.md` 和 `card.json`。它们明确是合成演练。真实研究使用自己的 suite、原始 runs、锁及相同的 `--cost-ledger`、`--artifacts`、`--verifiers`、`--corpus`（如有），不能把演示改名成实测。

**价值假设尚未验证**：作者可能愿意使用一个帮助定位和复现问题、减少试验准备与人工修正的工具。新增清单只是可供检验的产品交付，不证明作者会安装、愿意持续使用或已节省时间。

## 2. 冷启动：取消对“可信登记处”的前置依赖

`registry-view` 的 JSON/HTML 以及签名只读快照增加 `bootstrap` 状态。它描述本地持有的材料，不认证材料真实性：

| 状态 | 所持材料 | 不能推断 |
| --- | --- | --- |
| EMPTY | 无提交 | 社区或证据基础已经建立 |
| SYNTHETIC_ONLY | 只有合成研究 | 真实运行、收益或采用 |
| LOCAL_PILOT | 自报非合成的本地研究 | 外部研究或独立验证 |
| EXTERNAL_SUBMISSIONS_UNVERIFIED | 至少一项自报外部研究 | 身份、独立性或实际采用已认证 |

所有状态均保持 `trusted_evidence_layer=false` 和 `PROVISIONAL_LOCAL_FORMAT`；补证修订按研究谱系去重，独立样本数保持未知。签名和正向使用卡的既有核验继续有效，但不会把一个局部复核扩张为全登记处的权威。

冷启动仅推进**一个外部作者、一个窄能力、一次修复循环**，不扩建目录或增加平台功能。下一步材料必须由真实参与者提供：

1. 作者明确同意试用、选定实际任务，并决定材料的保存和分享范围；默认本地私用，不要求公开排名或好评。
2. 冻结配对任务、修复目标和时间/费用记录方法。既记录插件 WITH/WITHOUT，也单独记录作者使用 Value Lab 与其原有排查方法的准备、理解报告、修改和复测用时；二者是不同的价值问题，不能相互替代。
3. 保留两轮完整记录和改动摘要；作者说明采用了哪些诊断、忽略了哪些诊断以及原因。记录拒用、无帮助、误报和额外负担。
4. 非作者针对确切修订复核任务合理性和结论，说明身份关系、冲突及异议；输出可供对方复算的材料。
5. 只有外部实际复用、完整人工成本与直接反馈都能核对时，才讨论下一轮扩张。一个参与者的成功仍不建立普遍收益或行业标准。

没有完整计时就不声称节省时间；没有对照就仅作可用性访谈。若参与者拒用或完整收益不能覆盖使用负担，优先缩减记录与设置负担、修复核心路径；停止扩张。具体阈值须由参与者在收集前确定，不能事后挑选。本次没有邀请任何人，没有新增外部研究或独立评审。

## 3. 范围：默认入口真正关闭扩展

| 入口 | 默认 | 显式启用后 |
| --- | --- | --- |
| MCP | 6 个工具，评估、诊断与使用指导 | 增加 research_direction_advisor |
| 自动发现的技能 | assess-value、use-plugin-well | 研究技能需用户另行选择 |
| CLI | 不注册 research-* 与 team-card 子命令 | 兼容原实验命令 |
| 工作台 | 不载入研究/团队脚本，相关 API 和脚本 URL 返回 404 | 加载实验界面和路由 |

兼容源码和原记录保留，避免破坏既有数据；未新增运行模块、MCP 工具、核心命令或技能。研究技能移至 `extensions/research-directions/SKILL.md`，不在默认 `skills/` 中。扩展只做必要维护，晋升核心前必须有独立于配对测量的真实需求证据。

```sh
python scripts/value_lab.py --enable-extensions research-example
python scripts/value_lab.py --enable-extensions workbench
python scripts/value_lab.py --enable-extensions serve
```

全局开关放在子命令前。宿主若确实需要研究 MCP，应在它自己的启动参数中显式加入此开关，并明确选用扩展技能；默认发布配置保持关闭。Python 库仍兼容直接导入，不声称这是安全隔离机制。

## 本次验证应说明什么

回归检查覆盖清单中的两组失败/未知/缺失、全量复测、合成标识，登记处空白/合成/本地/自报外部阶段与修订去重，默认/启用后的 CLI、真实 stdio MCP 与 HTTP 入口，以及两项核心技能的打包发现。

历史真实试跑可以离线重新生成诊断，但不能算新增模型运行。源码摘要变化后，旧登记包应报告 `same_engine=false`，即使 `same_report=true` 也不声称同引擎重放。保留历史包，新的展示输出写入新目录。

本次工程验收与历史真实试跑分开记录在 `VERIFICATION.json`；外部采用、独立科学验证和真实节省时间仍未建立。

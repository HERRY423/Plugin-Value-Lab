# 研究方向诊断：从背景材料到下一步可检验的决定

这项能力帮助研究者回答：“我现在真正缺少什么？哪一步最值得先做？看到什么结果后应该改变方向？”它把插件的作用从评估一次执行的好坏，扩展到研究开始前和研究过程中的问题诊断。版本仍为 `0.4.0-alpha.1`。

它由两部分共同完成：宿主 Agent 阅读已授权材料、进行领域推理并形成方向；本地工具校验提交对象、整理证据与依赖、显示资源限制和修订差异。本地程序不调用模型，也不会仅根据关键词生成科学见解。安装后技能可被宿主选用；安装动作本身不会启动分析、监控文件或检索文献。

[Claude Code Plugin evals 官方文档](https://code.claude.com/docs/en/plugin-evals) 描述的重点是评估套件、评分、回归检查和无插件基线。本功能增加的是“该研究下一步应该理解什么、补什么证据”的工作流程；这是一项产品范围上的补充，不表示 Claude 的其他工具或生态没有研究辅助能力。

## 安装后可以怎样说

> 根据这份研究计划和已有结果，保留我的原始问题，分析哪些缺口会改变结论。请提出几个相互区分的方向，给出最强的替代解释、最便宜且有信息量的下一步，以及什么时候应该停止。已有材料可以读取；不要把未公开内容提交给外部服务。

> 我补充了一个结果，也不同意你之前关于批次混杂的判断。请保留上一版，更新证据和方向，说明哪些优先级因此变化、哪些分歧还没有解决。

用户不需要准备 JSON。Agent 负责把自然语言任务、实际读取的材料与自己的推理整理成结构化上下文；用户在对话中纠正判断，也可以在工作台“研究方向诊断”查看和修订。若只提供了一句研究主题，Agent 应先做有边界的初步分析，明确未知项；不能假装已经阅读数据或完成文献检索。

## 能带来哪些不同的工作方式

| 功能 | 改变的决定 | 证据边界 |
| --- | --- | --- |
| 问题与缺口地图 | 区分未知、局部覆盖、实质缺失和不适用，避免把所有未填项目都当成新课题 | 状态由提交者判断，不是自动科研完整性认证 |
| 证据到方向的追溯 | 看清方向依据什么、受哪条证据限制、依赖哪些先行工作 | 引用与依赖关系可检查，来源内容和科学解释仍需审阅 |
| 对手解释与停止信号 | 在继续投入前明确什么会推翻偏爱的解释，什么时候应缩小问题或停止 | 有停止条件不等于已完成实验或证明可证伪性 |
| 资源约束下的下一步 | 比较投入、时长、依赖和可获得的信息，保留未知费用 | 排序是透明的规划辅助，不是最优实验设计或价值估计 |
| 缺能力的精准交接 | 只有访问或操作能力确实不足时，才去发现插件 | 缺数据、缺独立重复、缺因果设计不能被“多装插件”替代 |
| 修订与分歧保留 | 新结果和研究者纠正能够改变路线，并可追溯前后依据 | 版本差异不是成果增长、研究收益或科学授权 |

## 分析如何展开

先固定研究者原话、背景和当前决定。区分“想解释的现象”“偏爱的假设”和“测量实际可以回答的问题”。例如，细胞比例的差异、个体层面的稳定差异与治疗的因果作用，是不同层次的问题。

接着建立证据清单。每条证据保留来源和状态，区分实际记录、他人报告、假设、未知与矛盾。已有摘要不足以证明原始数据满足条件；某条证据没有提供，也不自动代表它在项目中不存在。

然后审视与当前任务有关的十个维度：问题定义、数据、测量、研究设计、替代解释、稳健性、推广范围、可复现性、资源和实际影响。维度是提醒 Agent 认真推理的框架；并不要求研究者把每一项都变成实验。任何“不适用”都需要说明为什么。

对真正影响决定的缺口，形成几个方向。每个方向都应回答：为什么现在需要它、哪条证据支持这项担忧、有什么更简单或相反的解释、最小的区分性检查是什么、继续和停止的信号是什么。如果增加计算也无法区分两种解释，就需要明确指出需要不同的数据、设计、测量或专业判断。

最后根据预算、时间和依赖安排下一步。一次只推进少数能够改变决定的事项。未知费用和时长保持未知；不能因为未填写而视为免费或立即可完成。用户尚未给出资源限制时，提出条件化选项，不替用户承诺投入。

当前排序公式是“影响 × 不确定性 ÷ 工作量”，三个输入均为 1–5 的声明判断。系统依次选择依赖可安排、累计费用和时间不超限的方向，同分按 ID 排序，默认最多安排三个。它是可检查的贪心规则，不是对预期信息增益的测量，也不是最优组合求解。高分不替代领域判断；若优先级不合适，应修改有理由的判断或依赖，而不是把排序当作权威。

已声明预算或时间上限时，相应费用或时长未知的方向会标为需要估计，不会按零成本选入。未声明上限不代表资源无限，只是无法作相应约束检查。前置方向在同一批次中被选入，也只表示计划顺序；后续方向仍要等待前置结果核验。`accepted` 不表示前置实验已完成；被推迟或拒绝的前置方向会阻止下游直接安排。

## 教学例子：差异到底来自哪里

假设研究者提供的背景是：“处理组和对照组的某类细胞占比不同，想解释处理是否改变了细胞状态。”这只是虚构教学情景，不包含实测数据。

较浅的回答会直接列出差异分析、通路分析和一个新模型。更有用的诊断先检查：每组有哪些独立个体；处理与批次是否重合；测量能否区分比例变化和状态变化；原始问题是否要求因果解释。未提供的信息先标为未知。

一个候选方向是先检查个体和批次结构。它竞争的解释可能是“结果主要由批次或个体构成驱动”。最小下一步可以是读取已授权样本表、整理个体与批次交叉关系并检查是否有可识别的比较。如果处理与批次完全重合，继续增加复杂模型不能凭空恢复识别；此时可缩小为描述性结论、寻求额外设计信息，或规划新的采样。具体选择由真实材料和研究者的决定约束。

另一个方向可能是明确测量范围。若材料只有 RNA 测量，不能用计算输出替代实测蛋白变化。是否需要第二种测量取决于要作出的结论，而不是任何科研项目都必须追加一个模态。

上述推理必须由 Agent 根据实际背景完成。本地工具能检查这些方向是否有证据引用、替代解释、下一步、停止信号及合法依赖；不能判断这个具体研究设计是否真的合适。

## 通用研究例子：改版后留存下降，下一步先研究什么

另一个虚构情景是：“产品改版后整体七日留存下降，团队准备撤回新流程。”这里的决定是是否回滚，整体留存变化是待解释的报告，不足以直接确定原因。

可以提出三种相互区分的解释：新流程确有负面影响；新增渠道带来的用户构成变化拉低整体数字；埋点或留存口径在改版时改变。Agent 应先读取已授权的指标定义、发布时间和按渠道分组的汇总资料，保留尚未提供的信息为未知。

便宜的第一步通常可以设计为“核对前后指标口径与事件完整性，并检查相同渠道、同样观察窗口下的变化”，但是否可做要看实际材料。如果事件定义确实不一致，应先修复或重建可比指标，停止把原来的差值解释成产品影响。如果同类用户在一致口径下仍下降，这支持进一步调查，但没有随机分配时仍不能排除同期变化。

后续方向可以是访谈已流失和仍活跃用户、分析具体流失环节，或在适当条件下规划受控实验。方向间有顺序：口径未解决时，优先解释一个不稳定的数字通常不能支撑回滚决定。是否开展访谈、联系用户或启动实验，需要各自的任务授权；规划工具不会替团队执行这些动作。

这个例子展示的不是一套固定推荐，而是把“测量问题、选择效应、产品机制”分开，再根据能够区分它们的信息安排下一步。

## 与 Plugin Management 的分工

本插件先判断缺口类型；Plugin Management 或宿主处理能力发现、连接、依赖和明确请求的管理动作。

- 知识或证据缺口：先判断需要补读材料、审阅来源、重分析还是新实验，不自动寻找插件。
- 方法缺口：先判断已有工具和数据能否支持合适的方法；方法名称不等于方法适用性。
- 能力缺口：优先使用足够的原生能力，其次使用已连接插件；确有缺口时，只发送最少的公开能力关键词。
- 资源缺口：预算、时长、样本、设备和研究者投入需要真实约束，安装软件通常不能消除它们。

例如交接“文献引用检索”足够时，不应附带未公开研究假设、全文材料、本地路径或患者信息。建议插件不表示已安装，已安装不表示已连接，连接不表示它能支持当前科学结论。目录搜索、连接建议与实际执行仍遵循宿主和本会话的授权规则。

## 结构化上下文

MCP 工具名为 `research_direction_advisor`，支持 `action="diagnose"`、`"example"`、`"compare"`。工具是否已被宿主暴露，以当前可调用工具为准。

`diagnose` 接收 `context`；`compare` 接收 `before` 和 `after` 两个上下文；`example` 提供教学输入。示例不代表用户资料，也不能改个来源标签就当成真实结果。

上下文使用 `schema_version: 1`。以下是字段含义，Agent 通常负责构造这些对象：

| 字段 | 内容 |
| --- | --- |
| `evidence_type` | 可选 `synthetic / local`；教学输入为 `synthetic`，真实提交材料为 `local`，缺失则保留未声明；均不是独立验证 |
| `task` | `question`、`background`；可附 `decision`、`domain` |
| `evidence` | 每条含 `id`、`summary`、`source`、`status`；状态为 `observed / reported / hypothesis / unknown / contradicted` |
| `dimensions` | 以 `question / data / measurement / design / alternatives / robustness / generalization / reproducibility / resources / impact` 为键；各含 `status`、`rationale`、`evidence_ids` |
| `directions` | 每条含稳定 ID、标题、缺口类型、维度、依据、替代解释、下一步、继续与停止信号、依赖、规划判断与估计 |
| `constraints` | 可附 `budget_usd`、`hours_available`、`max_next_actions`（1–5） |
| `revision_note` | 可选，解释本次材料或判断为什么改变 |

方向字段为 `id`、`title`、`gap`、`kind`、`dimension`、`why_now`、`evidence_ids`、`alternative_explanation`、`next_test`、`success_signal`、`stop_signal`、`depends_on`、`impact`、`uncertainty`、`effort`、`cost_usd`、`hours`；可附 `capability_query` 与 `status`。

`kind` 为 `knowledge / evidence / method / capability / resource`。`impact`、`uncertainty`、`effort` 为 1–5 的规划判断，不是概率或科学质量分；`cost_usd`、`hours` 为非负有限数字或 null。方向状态为 `proposed / accepted / deferred / rejected`。`accepted` 只表示研究者接受该方向，不表示科学确认；未获得该决定时保留 `proposed`。

维度状态为 `covered / partial / missing / unknown / not_applicable`。证据引用和依赖必须指向已有 ID；不得为通过检查而虚构证据。上下文文件可能包含私有背景、原始问题和本地引用，分享或跨服务发送前应检查其内容。本地 MCP 处理不代表整个宿主对话都在本地运行。

缺省维度显示为未知；声明“已覆盖”却没有 `observed` 或 `reported` 状态的引用时，报告会显示支持不足；引用中含矛盾状态时会保留争议。这些检查只核对提交的标签与引用关系，不能证明来源确实支持相应判断，也不能把一个错误标签变成事实。未知引用、循环依赖、非法评分或非有限数值会被拒绝。

## 本地命令与修订

从插件根目录运行，或将脚本换成实际绝对路径：

```powershell
python scripts/value_lab.py research-plan .\context.json --output .\work\research-plan
python scripts/value_lab.py research-compare .\before-context.json .\after-context.json --output .\work\research-comparison.json
```

第一条校验并整理已经写入上下文的分析，在尚不存在或空的输出目录写入 `research-plan.json` 和 `RESEARCH.md`；已有非空目录不会被覆盖。第二条比较两份提交的上下文，写入指定比较文件。它们不自动检索文献、不运行实验、不安装插件、不扣款，也不替研究者作出批准。

当一项提议的检查有了新结果，单独保存一份 `update.json`，包含 `direction_id`、`result`、`source`、`signal` 和 `interpretation`。`signal` 只能是 `supports_favored`、`supports_rival`、`inconclusive` 或 `conflicting`；这是提交者的初步判断。运行：

```powershell
python scripts/value_lab.py research-followup .\context.json .\update.json --output .\work\followup-1.json
```

结果列出该方向、依赖它的下游方向及共享依据的方向，供研究者逐项重新审视。它不会修改原上下文、确认实验成功或解锁依赖。研究者确认后，再另存修订的上下文并用 `research-compare` 比较。工作台“有了新结果”提供相同的本地检查入口。

当研究者修正事实或提供新结果时，保留旧上下文，另存一份并填写修订原因。同一事项沿用稳定 ID，新的事项使用新 ID，真实分歧保留在理由和状态里。比较结果帮助发现新增、删除、改变的证据、缺口、方向与约束；任务对象改变时，明确显示背景条件发生变化。缺口数量减少可能只是状态或适用范围声明变化，报告不会把它当作缺口已经关闭，也不能独立判断新版本更正确。

## 怎样判断一次诊断有用

有用的诊断应能让研究者指出：“这条依据不对”“这个替代解释更重要”“这一步负担太高”“看到这个结果我就改变路线”。它的价值在于让研究选择可以检验、纠正和继续讨论，而不是给研究质量打一个漂亮的总分。

本地规则、测试、教学上下文和合法引用通过检查时，只能支持相应的软件行为。真实课题中的正确性需要相应领域证据；新颖性需要适当的文献检索；研究者收益需要实际使用证据。若要判断本工作流是否比普通 Agent 更有帮助，应另行设计匹配任务、相同材料与可解释评分的比较，使用 [插件价值评估](../skills/assess-value/SKILL.md)。

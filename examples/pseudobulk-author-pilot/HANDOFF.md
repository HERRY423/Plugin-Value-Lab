# 从自己的问题开始

目的：让你用自己的插件问题获得一项有证据的诊断，或知道为什么目前无法判断。不要先阅读旧案例答案，也不要求先学会配置评测器。尚无真实参与者结果；本页只是可转交的操作材料。

## 你提供三件事

1. **实际问题**：你让哪个插件做了什么，什么结果令你困惑？尚未运行也可以。
2. **可使用的材料**：插件位置、允许读取的输入／结果／日志路径；不要提供密钥。先说明哪些材料不可发送给外部服务。
3. **可用结果**：结果将用于什么判断？什么错误不可接受？不知道标准答案时直接说不知道。

把以上信息与下面这段话交给能够访问本地 PVL 的当前 Agent：

> 请使用本地 Plugin Value Lab 帮我检查这个真实问题。先读我的问题和允许使用的材料，选择现有诊断、对话式评测创建或修复复测路径；不要让我填写 verifier JSON。先给出中文任务说明、成功标准和缺失材料。已有产物先检查原件；没有标准答案就保留未知。把问题、证据位置、违反的任务要求、替代解释和下一步检查放在诊断首屏。执行前说明实际模型、材料外发与费用，沿用已有授权；不要自动重试未知结果。不要替我记录理解、确认、反馈或人工作业时间。

## Agent 如何选择路径

| 你当前有什么 | 使用既有能力 | 本次可交付结果 |
| --- | --- | --- |
| 已有产物和明确任务标准 | `diagnose`，科学方法由原任务决定 | 具体失败／通过／未知及证据；BH 不是默认通用标准 |
| 尚无结果，想评估自己的插件 | `init` 来源包 → Agent 方案 → `init --proposal --materials` 校准 | 中文 RESEARCH-PLAN.md；准备和校准不算插件实跑 |
| 已有供者配对计数任务 | 本目录 prepare.py 与 RUNBOOK.md | 输入映射与待审阅契约；参考计算需显式执行 |
| 已修复且保留完整原生材料 | `compare-native-repair` | 同条件复测报告与未闭合环节 |

无需为第一次诊断注册证据库、设置排行榜或启动额外服务。任务不适合现有判据时说明限制，不将科学问题降级成词语匹配。

## 试跑记录

从第一次打开资料起计时，包括安装、阅读、找文件、求助、失败和放弃。计时程序尚未启动的部分用原有计时工具记录；没有记录的时间保持未知。Agent 只整理你实际提供的事实。

只做一次可用性试跑时，在 session.json 中由操作者填写真实代号、`arm=with_pvl`、`task_pair=not-compared`、`order=1` 与既有接触；maintainer_or_ai 必须如实。STUDY-PLAN.md 明确写“单臂可用性，不评价节省时间”，填写本人的真实问题、允许材料、停止点、审阅要求，其余比较项标不适用并说明原因。之后按 RUNBOOK.md 启动 observe.py。后续有／无 PVL 比较必须另行冻结分配计划，不能把本次试跑追认为对照实验。

完成后，请用自己的话解释：你认为问题是什么、证据在哪、哪里还不能确定、下一步是什么。生成报告但没有理解，照实记录。卡住或放弃同样交回；缺少数据、参考或审阅者时停止依赖它们的步骤。

## 交回什么

交回原始观察日志、自己的解释、报告、全部失败尝试和待解决项。保留原件，再制作脱敏副本；不必交回完整私有数据。审阅状态先写待审阅。没有获得允许，不自动发送给他人。

本文用于 WITH_PVL 可用性试跑。未来做对照时，未暴露的基线参与者只接收 BASELINE.md、中性计时工具及其任务；不能提前收到本页、诊断、参考答案或完整 PVL 包。
